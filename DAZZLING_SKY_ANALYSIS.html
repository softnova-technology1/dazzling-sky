02 · Critical & System Failures

Complete Errors Report (6 Identified)

Severe compile, runtime, deployment, and security vulnerabilities that must be resolved.

ERR-01 · FATAL DEPLOYMENT CRASH

Linux Case Sensitivity Crash (models/user.js vs User.js)

On Windows, NTFS is case-insensitive, allowing require('../models/User') to load user.js. On any Linux production environment (AWS, Render, Vercel, Docker, DigitalOcean), Node.js enforces strict case-sensitivity. The server crashes immediately on launch with Error: Cannot find module '../models/User'.

📍 Backend/controllers/userController.js:1 · adminController.js:3 · models/user.js
Critical
Current Broken State (user.js)
// File on disk: Backend/models/user.js (lowercase)
// In userController.js & adminController.js:
const User = require('../models/User'); // ❌ Throws Cannot find module on Linux
Permanent Solution
// Rename file to PascalCase matching all other models:
// git mv Backend/models/user.js Backend/models/User.js
const User = require('../models/User'); // ✅ Works across all OS platforms
ERR-02 · CRITICAL SECURITY EXPOSURE

Public Unauthenticated Admin Setup Endpoint (/api/auth/setup)

The endpoint POST /api/auth/setup is mounted without any authentication, secret key, or environment check. It creates an admin with hardcoded credentials and returns the plaintext username and password in the HTTP response body: "Initial admin created successfully (admin@dazzlingsky.com / admin123)". Any visitor can discover this endpoint and attempt default credential logins.

📍 Backend/routes/authRoutes.js:11 · Backend/controllers/authController.js:46
Critical
Vulnerable Implementation
// authRoutes.js
router.post('/setup', authController.createInitialAdmin); // ❌ Publicly open!

// authController.js
res.status(201).json({ 
  message: 'Initial admin created (admin@dazzlingsky.com / admin123)' 
});
Secured Implementation
// Protect with a one-time server initialization token or remove entirely:
router.post('/setup', (req, res, next) => {
  if (req.headers['x-setup-key'] !== process.env.ADMIN_SETUP_SECRET) {
    return res.status(403).json({ message: 'Forbidden' });
  }
  next();
}, authController.createInitialAdmin);
ERR-03 · CRITICAL ACCESS CONTROL FAILURE

Zero Authentication on Product Mutation (POST / PUT / DELETE)

While adminRoutes.js and orderRoutes.js protect administrative actions, productRoutes.js mounts POST /, PUT /:id, and DELETE /:id with NO middleware. Any anonymous internet user can wipe out every single product or modify catalogue prices without logging in.

📍 Backend/routes/productRoutes.js:28-30
Critical

router.delete('/:id', adminMiddleware, productController.deleteProduct);

Frontend components make direct fetch() calls to http://localhost:5000 rather than an environment-configured API base URL. When deployed to Vercel, Netlify, or accessed from a phone or client device, all network requests fail with connection refused errors.

📍 AuthPopup.js, AdminLogin.js, CustomersManagement.js, DashboardOverview.js, OrdersManagement.js, ProductsManagement.js, Cart.js, Payment.js, ProductDetails.js, Shop.js

No Stock Deduction or Inventory Validation Upon Order Placement

Product.js schema contains a stock field, but orderController.createOrder never checks whether items are in stock, and never decrements inventory. Customers can purchase out-of-stock items repeatedly, leading to negative stock and fulfillment chaos.

Client-Controlled Order Pricing (Zero Backend Validation)

orderController.js blindly trusts req.body.totalPrice, taxPrice, and shippingPrice sent from the client without recalculating them against actual database product prices. Any user using Postman or browser DevTools can submit an order with totalPrice: 0.01 and the backend accepts and logs it.

📍 Backend/controllers/orderController.js:7, 18-24

Backend/models/user.js defines cart.product as mongoose.Schema.Types.ObjectId. However, Frontend/src/data/productsData.js uses numeric IDs (id: 1, 2, 3). When a logged-in user adds a static product to the cart and triggers /api/users/cart/sync, Mongoose throws a CastError: Cast to ObjectId failed for value "1", returning HTTP 500.

📍 Backend/models/user.js:23 · Frontend/src/pages/cart/Cart.js:70

04 · Journey Diagnostics

Workflow Breaking Issues (6 Major Failures)

Points where real customer journeys or administrative workflows completely break down.

01

Checkout & Payment Simulation (No Real Gateway)

The Problem: The user enters their actual cardholder name, card number, expiration, and CVV on Payment.js. The application validates input length, then completely discards the card data, calls /api/orders, and accepts the order. Zero dollars are charged. No payment gateway (Stripe, PayPal, Razorpay) is integrated.

⚠️ Impact: Massive financial loss (free orders), customer confusion, and serious PCI DSS compliance violations for capturing unencrypted card data without tokenized iframes.

02

Order Confirmation Screen Displays Beverly Hills Mockup Data

The Problem: When checkout completes, OrderConfirmed.js renders hardcoded placeholder text: address: '123 Luxury Lane, Apt 4B, Beverly Hills, CA 90210', paymentMethod: 'Credit Card (ending in 4321)', and a random math-generated Order ID (DS-######).

⚠️ Impact: Every customer, regardless of real shipping address or actual order ID, sees that their luxury bouquet is being delivered to Beverly Hills with card 4321.

03

Blog Navigation Driven by State Instead of URL Routes

The Problem: In App.js, clicking "Read More" on a blog post updates selectedFlower in component state instead of navigating to a dedicated URL (e.g. /blog/:id or /blog/:slug).

⚠️ Impact: Refreshing the browser instantly kicks the user back to the blog index. Browser "Back" button leaves the blog entirely. Articles cannot be shared, bookmarked, or indexed by Google SEO.

04

Product Images Disappear on Cloud Deployment (Ephemeral Disk)

The Problem: Multer stores product uploads to the local uploads/ directory. Modern containerized or serverless hosting platforms (Render, Heroku, Railway, Vercel) have ephemeral file systems.

⚠️ Impact: Every time the backend restarts or deploys a code update, all admin-uploaded product photos are completely erased.

05

Fragile Personal Gmail SMTP Without Queuing or Retry

The Problem: sendEmail.js creates a direct Gmail SMTP connection per order. Gmail imposes strict daily sending thresholds, blocks accounts flagged for automated traffic, and rejects logins without App Passwords.

⚠️ Impact: Silent email failures when order volume spikes, no retry mechanism, and delivery blacklisting.

06

Unrestricted CORS & Lack of Brute-Force Rate Limiting

The Problem: server.js uses app.use(cors()) without origin whitelisting, and contains no rate limiter (e.g. express-rate-limit) on authentication endpoints.

⚠️ Impact: Vulnerable to credential stuffing attacks on customer/admin logins and API abuse.
